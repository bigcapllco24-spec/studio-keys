## What the lead found (check it, don't trust it blindly)
- `src/assistant.js` `startListening()` calls `micStart()` when humming is on (`ASSIST.hum && !MIC.on`), but `stopListening()` never calls `micStop()`. So after "Always listening" is turned off, the microphone stays open (browser mic indicator stays on) and the pitch tracker keeps running.
- Each `startListening()` makes a new `SpeechRecognition` whose `onend` restarts it while the global `ASSIST.listening` is true. A quick off → on leaves the OLD recogniser restarting too (two listeners). Restarts should be tied to the recogniser that is current (`ASSIST.rec===rec`).
- The one-shot orb tap: when "Always listening" is on, tapping the orb only re-arms; check whether there is any other "off" control (phone layout on `preview-ux-4` is not on main yet; only fix main, but note in your report anything UX-4 must keep).
- The `asHum` checkbox change handler starts the mic but never stops it when humming is turned off.
- Also check `store.get('asListen')` and boot: listening must not switch itself back on after a reload unless that is what the code intends (report what you find; don't change the setting's meaning without saying so).

## Done when
After the user turns listening off (the "Always listening for my name" toggle, or any off control): speech recognition stops and is not restarted, the microphone is released if listening opened it (MIC.on false, stream tracks stopped) — but NOT if the user opened it themselves with the Mic button or a sung take is running (respect `TAKE.micByTake` / take state), the orb shows idle, and no speech or hum is picked up until the user turns it on again. Turning humming off while listening closes a mic that listening opened. Off → on → off quickly leaves zero live recognisers.
