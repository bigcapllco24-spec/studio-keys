## The bugs (tester's daily session, 16 Nov; full report `.claude/work/reports/QA-1-daily-2026-11-16.md`, screenshot /tmp/qa/2026-11-16/shots/p3b-copy-undo.png)
1. **HIGH — Undo after "Save a copy" goes back into the original song and overwrites it.** New song → "drums like Charlotte de Witte" → "add a bassline" → Save → Save a copy (title "Original (copy)") → Undo: the title switches back to "Original" and every later change or Undo autosaves into the original. In a longer run the saved original went from 174 BPM / 1 track to 78 BPM / 0 tracks, and stayed that way after reload.
   - Lead's read (check it): `saveCopy()` in `src/daw.js` (line ~321) swaps `PROJ.id`/name but never resets the undo history, so Undo's `applyState` (src/edit.js) restores the original's state — including its id — and autosave writes it. Look at how `loadNamed()`/`newSong()` reset undo (`undoReset()`?) and do the same; also make sure no undo snapshot can ever carry a different project id back in (defence in depth: undo restores content, not identity).
2. **MEDIUM — A tempo typed in the BPM box (or set with Tap) is not an undo step.** "hip hop beat at 88 bpm like J Dilla" → "add chords" → type 96 in BPM, Enter → Undo: the chords AND the tempo go back → Redo: chords back, tempo stays 88 (the 96 is lost).
   - Lead's read: `setTempo()` in `src/studio.js` (line ~49) never calls `saveProject()` (or whatever pushes an undo step). Make a box/Tap tempo change one undo step (Tap: one step for the final tempo, not one per tap — debounce), and keep Undo/Redo of tempo exact. Check the assistant's tempo changes still make exactly one step (no double steps).
3. **Rough edge, same area — deleting the song you're in comes back.** Open song… → Delete on the current song → confirm: it leaves the list, but your next change saves it again. Decide the sane behaviour (recommended: deleting the current song leaves you in an unsaved new copy that only saves if you change something, and the list doesn't show the deleted name again) and say what you chose in the report.

## Done when
Save a copy starts its own undo history and the original song is never changed by anything done in the copy (check in IndexedDB: the original's tracks/bpm/savedAt unchanged after 10 edits + 10 undos in the copy, and after reload). A BPM-box or Tap tempo change is exactly one undo step; Undo and Redo both restore the right tempo. A deleted current song doesn't reappear in the list. Everything else about undo, autosave and the songs list behaves as before.
